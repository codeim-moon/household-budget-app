# 가계부 (Household Budget App)

순수 HTML / CSS / JavaScript로 만든 개인·가족용 월간 가계부 웹 앱입니다. 프레임워크, 빌드 도구, 서버 배포 과정 없이 `index.html`을 브라우저로 직접 열기만 하면 바로 사용할 수 있습니다.

## 실행 방법

1. 이 저장소를 내려받거나 클론합니다.
2. `index.html` 파일을 더블클릭해서 브라우저(Chrome, Edge 등)로 엽니다(정적 파일 서버로 열어도 됩니다).
3. 이메일/비밀번호로 로그인하거나 회원가입합니다. 인터넷에 연결되어 있어야 로그인과 거래 데이터 조회/저장이 가능합니다(아래 "데이터 저장 방식" 참고).

## 파일 구성

| 파일 | 설명 |
| --- | --- |
| `index.html` | 앱의 전체 구조(로그인 화면, 홈/예산/분석/설정 탭, 거래·예산·반복거래 등록 모달, 로딩/오류 화면) |
| `style.css` | 흰 배경 + 블루 포인트의 미니멀한 반응형 디자인 (360px 모바일부터 대응) |
| `app.js` | 상태 관리, Supabase 인증·데이터 저장/로드, localStorage 저장/로드, 렌더링, 이벤트 처리를 담당하는 순수 JS 로직 |
| `household_budget_app_prd.md` | 최초 작성한 제품 요구사항 문서(PRD) |

## 주요 기능

- **로그인**: 이메일/비밀번호로 로그인·회원가입. 계정마다 거래 내역이 완전히 분리되어, 같은 계정으로 다른 기기·브라우저에서 로그인해도 동일한 데이터를 봅니다.
- **홈**: 월 이동, 사용자(본인/가족/공용 등) 필터, 이번 달 남은 돈·총수입·총지출 요약, 검색/유형/카테고리 필터와 결과 합계, 거래 등록·수정·삭제(삭제 확인 포함)
- **예산**: 월 전체 예산 및 카테고리별 예산 설정, 사용액·남은 예산·사용률(%) 표시, 예산 초과 시 강조 표시
- **반복 거래**: 시작월~종료월을 지정하면 매달 자동으로 거래 생성, 새로고침해도 중복 생성되지 않음
- **분석**: 카테고리별·사용자별 소비 비중, 고정지출 vs 개인지출 비교, 전월 대비 소비 증감, 최근 6개월 수입·지출·남은 돈 추이. 저축·투자는 "남은 돈" 계산에는 지출로 포함하되 소비 분석에서는 별도로 집계
- **설정**: 로그인 계정 표시·로그아웃, 사용자·소분류(3단계 카테고리: 유형 > 중분류 > 소분류) 추가/이름 수정/숨기기

## 데이터 저장 방식

- **거래(수입/지출) 내역**: [Supabase](https://supabase.com) Auth로 로그인한 계정에 귀속되어 Postgres의 `income_expense_lists` 테이블에 저장됩니다. 각 행은 로그인한 사용자의 `auth.uid()`를 담은 `user_id` 컬럼을 가지고 있고, DB의 Row Level Security(RLS) 정책이 "본인(auth.uid() = user_id) 행만 조회·수정·삭제 가능"하도록 강제합니다 — 즉 실제 계정 로그인이 곧 보안 경계입니다.
- **사용자·카테고리·예산·반복 거래 규칙**: 계정과 무관하게 브라우저 `localStorage`에 저장됩니다(한 가구가 함께 쓰는 브라우저에서 공유하는 값이라고 보면 됩니다).
  - `household-budget:members`, `household-budget:categories`, `household-budget:budgets`, `household-budget:recurring`
- **로그인 이전(3단계) 데이터 마이그레이션**: 로그인 기능이 없던 이전 버전에서는 브라우저마다 `crypto.randomUUID()`로 만든 `owner_key`(`localStorage`의 `household-budget:ownerKey`)로 거래를 구분했습니다. 최초 로그인 시, 이 브라우저에 `owner_key`로 남아있던(아직 어떤 계정에도 연결되지 않은) 거래가 있으면 자동으로 로그인한 계정 소유로 가져옵니다.

### ⚠️ 보안/개인정보 관련 안내

Supabase `anon`/publishable key는 `app.js` 소스코드에 그대로 포함되어 있습니다(정적 사이트 특성상 불가피하며, Supabase가 의도한 사용 방식이기도 합니다). 이 키만으로는 아무 데이터도 볼 수 없고, 반드시 이메일/비밀번호로 로그인해서 발급받은 본인의 세션(JWT)이 있어야 RLS 정책을 통과해 본인 소유 행에만 접근할 수 있습니다. 다만 이메일 인증(Confirm email)이 켜진 프로젝트라면 회원가입 후 확인 메일의 링크를 눌러야 로그인이 가능합니다.

## 알려진 제한사항

- 인터넷 연결이 없으면 로그인하거나 거래를 불러오고 저장할 수 없습니다(오류 화면과 "다시 시도" 버튼이 표시됩니다).
- 사용자·카테고리·예산·반복 거래 규칙은 계정이 아니라 브라우저에 저장되므로, 같은 계정이라도 다른 기기·브라우저에서는 이 항목들을 새로 설정해야 할 수 있습니다(거래 내역만 계정을 통해 공유됩니다).
- 브라우저 저장소(`localStorage`)를 지우면 사용자·카테고리·예산·반복 규칙 설정이 사라집니다(거래 내역은 계정에 남아 있어 다시 로그인하면 그대로 보입니다).
